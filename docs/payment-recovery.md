# 자동 결제 확인과 취소

사용자는 주문을 조회해 결과를 확인합니다. 브라우저의 조회는 `GET /orders/{orderId}`로 DB를 읽으며, 결제 복구를 실행하지 않습니다. 서버는 브라우저가 닫혀도 미확정 결제를 자동 처리합니다.

## 처리 순서

1. `PaymentService.confirm()`이 주문 금액을 검증하고 `PROCESSING`과 결제키를 먼저 저장합니다.
2. 토스 승인 응답을 저장합니다. 정상 결제는 `SUCCEEDED`, 확정 거절은 `FAILED`, 불명확한 응답은 `UNKNOWN`입니다.
3. `PaymentRecoveryConfiguration`이 기본 5초 간격으로 `PaymentRecoveryService`를 실행합니다. 작업은 `next_action_at`이 지난 결제를 최대 20개씩 확인합니다.
4. 저장된 결제키로 토스 GET 조회를 보냅니다. 같은 주문·키이고 금액·통화가 일치하는 `DONE`은 성공으로 복구합니다.
5. 같은 주문·키의 `DONE`인데 금액·통화가 다르면 `CANCEL_PENDING`, 실제 승인 금액·통화, 취소 멱등키와 시작 시각을 **취소 호출 전에 DB에 저장**합니다.
6. `POST /v1/payments/{paymentKey}/cancel`에 고정된 취소 사유와 멱등키를 보냅니다. `cancelAmount`를 생략하여 전액 취소합니다.
7. 토스의 `CANCELED`, 잔액 0, 성공한 취소 이력과 시각을 확인한 뒤 `CANCELED`로 저장합니다. 승인 내역과 취소 시각을 주문 조회에서 함께 반환합니다.

`readResult()`는 HTTP 응답의 의미만 해석합니다. DB 저장과 재조회·취소 순서는 `PaymentRecoveryService`가 담당합니다. 취소를 시작한 결제를 이후 승인 성공으로 되돌리지 않습니다.

## 중단과 재시도

- 최초 `PROCESSING`은 2분 후 조회 대상이 됩니다. 승인 응답을 저장하지 못하거나 프로세스가 종료되어도 남은 결제키로 재조회합니다. 새로운 승인은 요청하지 않습니다.
- `UNKNOWN`은 최초 5초 뒤 재조회합니다. 이후 실패마다 대기 시간이 늘어나 최대 5분 간격이 됩니다.
- 작업자는 `next_action_at`을 5분 뒤로 옮긴 변경을 먼저 저장해 선점합니다. `@Version`이 동시 선점과 늦은 결과의 덮어쓰기를 막습니다. 네트워크 대기 동안 DB 트랜잭션을 유지하지 않습니다.
- 취소 응답 유실·취소 후 DB 저장 실패도 다음 작업에서 **조회부터** 합니다. 이미 취소됐다면 결과만 저장합니다. 아직 같은 승인 상태라면 DB에 보관한 멱등키로 취소를 재시도합니다.
- 취소 멱등키와 사유를 재시도마다 바꾸지 않습니다. 최초 취소 의도 기록 후 14일을 넘기면 자동 재전송을 중단합니다. 토스 멱등키는 15일간 유효합니다.
- 자동 복구는 최대 10회입니다. 계속 확인되지 않으면 `REVIEW_REQUIRED`와 `PAYMENT_REVIEW_REQUIRED` 오류 로그를 남깁니다. 운영 환경에서는 이 로그에 알림을 연결하고 토스 상점 내역과 대조해야 합니다. 외부 알림 전송과 관리자 처리 화면은 포함하지 않습니다.

## 자동 취소 대상의 범위

카드·국내 간편결제에서 **저장된 주문번호와 결제키가 모두 일치하는 거래의 승인 금액·통화 불일치**만 자동 취소합니다. 주문번호나 결제키 자체가 다르면 다른 거래일 수 있으므로 `REVIEW_REQUIRED`로 남깁니다. 부분 취소 상태와 미지원 결제수단도 운영자가 확인합니다. 빈 응답·시간 초과·404만으로 결제를 취소하거나 실패로 확정하지 않습니다.

DB 저장 장애만 발생한 정상 승인은 조회하여 성공으로 복구합니다. 단순히 DB 저장이 한 번 실패했다는 이유로 정상 결제를 취소하지 않습니다.

## 화면과 API

수동 `/payments/{orderId}/reconcile` API와 PG 재확인 버튼은 제거했습니다. 결과 화면과 주문 화면은 처리 중인 주문을 3초 간격으로 읽고, 성공·실패·취소 완료·확인 지연 상태에 도달하면 조회를 멈춥니다. 주문 조회는 주문 금액과 실제 승인 금액, 승인 시각, 취소 시각을 구분해 보여줍니다.

고객 임의 취소 API는 노출하지 않습니다. 이 기능은 서버가 확인한 결제 불일치를 처리하기 위한 내부 자동 취소입니다. 프로젝트는 여전히 테스트 키만 허용합니다.

## DB 및 검증

`V3__automatic_payment_recovery.sql`은 기존 데이터를 유지하며 자동 처리에 필요한 컬럼과 상태 제약을 추가합니다. 기존 `PROCESSING`·`UNKNOWN`도 재시도 대상으로 예약합니다.

모의 HTTP 테스트는 승인·조회·취소 계약과 응답 검증을 확인합니다. PostgreSQL 통합 테스트는 취소 의도 선저장, 응답 유실, 저장 장애, 서버 메모리에 의존하지 않는 재시도, 중복 작업자, 재시도 한도를 검증합니다. 프런트엔드 테스트는 자동 결과 조회의 종료와 화면 이탈 시 중단을 확인합니다.
