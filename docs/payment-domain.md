# 처음 배우는 결제 서비스

결제 서비스를 처음 만들어보는 사람을 위한 문서입니다. 지금은 작은 쇼핑몰의 기본 흐름부터 이해하고, 공부하고 구현하는 순서에 맞춰 이 문서에 내용을 조금씩 추가합니다.

여기서 **도메인**은 “결제 업무에서 사용하는 개념과 규칙”이라는 뜻입니다.

## 1. 우리가 만들 예시

티셔츠 한 장을 **10,000원**에 파는 쇼핑몰을 생각해봅시다. 배송비와 할인은 없고, 고객은 카드로 결제합니다.

고객은 티셔츠를 주문하고, 결제하고, 나중에 배송받습니다. 우리는 이 과정에서 **어떤 주문에 대해 결제가 완료됐는지 기록하는 기능**을 먼저 만들려고 합니다.

## 2. 토스페이먼츠는 어떤 역할을 하나요?

결제에는 다음 참여자가 있습니다.

| 참여자 | 하는 일 |
| --- | --- |
| 고객 | 상품을 고르고 카드로 결제합니다. |
| 우리 쇼핑몰 | 주문과 가격을 저장하고, 결제를 요청하고, 결과를 기록합니다. |
| 토스페이먼츠 | 쇼핑몰과 카드사 사이에서 결제 처리를 연결합니다. |
| 카드사 | 카드 사용자의 인증과 결제 승인 등을 처리합니다. |

이때 토스페이먼츠 같은 결제 대행사를 **PG**라고 부릅니다. 우리 쇼핑몰은 토스페이먼츠와 연동해서 카드 결제를 받을 수 있습니다. [토스 공식 설명](https://docs.tosspayments.com/resources/glossary/card-payment)

## 3. 주문부터 결제 완료까지

1. **고객이 주문합니다.** 우리 서버에 “티셔츠 1장, 10,000원, 결제 대기”로 저장합니다.
2. **결제 화면을 엽니다.** 고객이 결제하기 버튼을 누르면 토스페이먼츠의 결제 화면으로 진행합니다.
3. **고객이 카드 인증을 합니다.** 카드 앱에서 비밀번호 등을 입력합니다. 아직 우리 쇼핑몰의 결제 처리가 끝난 것은 아닙니다.
4. **우리 서버가 결제 승인을 요청합니다.** 저장된 주문과 결제금액이 맞는지 확인하고 토스페이먼츠에 승인을 요청합니다.
5. **승인 결과를 확인하고 저장합니다.** 결제가 성공한 것을 확인하면 해당 주문을 “결제 완료”로 기록하고 고객에게 보여줍니다.

**카드 인증을 마친 것과 결제가 최종 완료된 것은 구분해야 합니다.** 우리 서버가 승인 결과를 확인하는 단계까지 있어야 합니다. [토스 공식 결제 흐름](https://docs.tosspayments.com/guides/v2/get-started/payment-flow)

## 4. 결제했다고 배송과 입금까지 끝난 건가요?

주문 하나에도 서로 다른 일이 진행됩니다.

| 개념 | 확인하려는 것 | 티셔츠 예시 |
| --- | --- | --- |
| 주문 | 무엇을 얼마에 구매했나요? | 티셔츠 1장, 10,000원 |
| 결제 | 고객의 결제가 완료됐나요? | 카드 결제 승인 완료 |
| 상품 제공 | 고객에게 상품을 전달했나요? | 티셔츠 배송 완료 |
| 정산 입금 | 판매대금이 사업자 계좌에 들어왔나요? | 수수료 등을 반영한 금액 입금 |

**결제 완료와 상품 제공 완료:** 월요일에 결제하고 수요일에 티셔츠를 받는다면, 월요일에는 결제만 완료된 상태입니다. 결제 후 배송에 문제가 생기면 “결제 완료, 배송 문제 발생”으로 기록하고 해결해야 합니다.

온라인 강의라면 배송 대신 이용권 발급이 상품 제공에 해당합니다. 결제는 성공했지만 이용권 발급이 실패할 수도 있습니다.

**결제 완료와 정산 입금:** 고객이 월요일에 카드로 결제해도, 사업자 계좌에는 계약에서 정한 정산 일정에 따라 대금이 들어옵니다. 결제금액에서 수수료 등이 반영되므로 고객이 결제한 금액과 사업자가 받는 금액도 다를 수 있습니다. [토스 공식 정산 설명](https://docs.tosspayments.com/resources/glossary/settlement)

날짜를 임의로 정해보면 다음과 같습니다. 실제 정산일은 상점 계약에 따라 달라집니다.

| 시점 | 고객 결제 | 상품 배송 | 사업자 정산 입금 |
| --- | --- | --- | --- |
| 월요일 | 완료 | 준비 중 | 대기 |
| 수요일 | 완료 | 완료 | 대기 |
| 계약에 따른 정산일 | 완료 | 완료 | 입금 확인 |

그래서 **결제 상태, 배송 상태, 정산 상태를 따로 기록**합니다. 지금은 이 세 가지가 서로 다른 일이라는 것만 이해하면 됩니다.

## 5. 고객이 취소하면 어떻게 하나요?

아직 티셔츠를 보내지 않았다고 가정해봅시다.

- **결제 전 취소:** 주문을 취소하면 됩니다. 받은 돈이 없으므로 돌려줄 돈도 없습니다.
- **결제 후 취소:** 주문 취소와 함께, 이미 결제한 10,000원을 돌려주는 처리가 필요합니다.

결제 후에는 우리 서버가 토스페이먼츠에 결제 취소를 요청하고 결과를 확인합니다. 우리 DB의 주문 상태만 “취소”로 바꾼다고 카드 결제까지 취소되는 것은 아닙니다.

PG에서 취소를 처리한 뒤에도 고객 카드에 반영되기까지는 시간이 걸릴 수 있습니다. [토스 공식 취소 설명](https://docs.tosspayments.com/guides/v2/cancel-payment)

## 6. 처음에는 어디까지 만들어볼까요?

첫 학습 범위는 아래 네 가지로 잡습니다.

1. 티셔츠 10,000원 주문을 만들기
2. 토스페이먼츠 테스트 결제 진행하기
3. 서버에서 주문금액을 확인하고 결제 승인 결과 저장하기
4. 주문을 조회해서 결제 결과 확인하기

이 흐름을 이해하고 구현한 뒤 **전액 취소 → 중복 요청·통신 오류 처리 → 부분 환불·정산 관리** 순서로 필요한 내용을 이 문서에 추가합니다.

현재 목표는 “주문을 만들고, 결제를 진행하고, 그 결과를 확인하는 과정”을 직접 설명할 수 있게 되는 것입니다.
